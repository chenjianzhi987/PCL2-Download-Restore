# PCL 2.99.0.0 下载功能阻断点分析

> 分析对象：`Plain Craft Launcher 2.exe` 2.99.0.0（2026-10-20 发布）
> 官方基准 SHA-256：`6b6e1260cb5a1d6a303855f1c60cab3d0bc1aebba7e40a964180188b271e7386`
> 对照样本：2.13.1.1（2026-08-07 构建，下载功能正常）
> 方法：Mono.Cecil 反编译 + IL 规范化哈希逐方法对比 + 运行时日志验证

## 1. 结论

下载渠道没有被"封网"，也没有服务端开关，**阻断发生在客户端一个方法里**：

`PCL.PageDownloadInstall::LoaderInit()` 把页面本该使用的共享加载器
`ModDownload.DlClientListLoader` 换成了一个临时新建的 `LoaderTask`（名字叫「关闭下载」），
后者的完成回调直接抛异常，异常消息就是界面上的那句
「为遵守相关法律法规，PCL 暂时不再提供 MC 下载功能，非常抱歉 qwq……」。

下载模块本体（`ModDownload` 里的全部 loader、Mojang/BMCLAPI 双源、安装流程）**完整保留**，
只是不再被下载页引用。

## 2. 证据一：服务端没有关停

| 检查项 | 结果 |
|---|---|
| `pcl2-server-1253424809.file.myqcloud.com/minecraft/download.json` | 403（被删/被拒） |
| 同上 `ServerConfig.json` | 403 |
| 旧版 2.13.1.1 实际下载 | **正常**（本机下载过 lwjgl 全量库） |
| `launchermeta.mojang.com/mc/game/version_manifest.json` | 200 |
| `bmclapi2.bangbang93.com/mc/game/version_manifest.json` | 200 |

结论：download.json / ServerConfig.json 的 403 与下载功能无关（旧版不依赖它们下载），
网络侧也没有新增封禁。

## 3. 证据二：限制文案只被 5 处引用

在 2.99.0.0 的 IL 中搜索 `为遵守相关法律法规`，命中 5 个方法：

| # | 方法 | 2.99 里的形态 | 是否影响功能 |
|---|---|---|---|
| 1 | `PCL.PageDownloadInstall/_Closure$__::_Lambda$__3-0` | `ldstr 限制文案; newobj Exception; throw` | **是**（下载页入口） |
| 2 | `PCL.ModModpack::ModpackInstall()` | 整个方法 = 提示后返回 | **是**（手动装整合包入口） |
| 3 | `PCL.ModModpack::ModpackInstall(string,string,string)` | 仅 catch 兜底分支被换成限制文案 | 否（只影响报错文案） |
| 4 | `PCL.FormMain/_Closure$__25-0::_Lambda$__0` | 拖入文件时若异常消息等于限制文案就提示 | 否（拖入流程本身在） |
| 5 | `PCL.FormMain::ShowUpdateLog(int)` | 更新日志里的「删除：…」条目 | 否（纯文本） |

## 4. 证据三：受限 loader 的调用链

`_Lambda$__3-0` 只被 `_Lambda$__R3-3` 调用；`_Lambda$__R3-3` 只被 `LoaderInit` 引用：

```
LoaderInit
  └─ new LoaderTask("关闭下载", <Action: _Lambda$__R3-3>, null, 2)
  └─ PageLoaderInit(LoadMinecraft, PanLoad, PanAllBack, null, <该 loader>, _Lambda$__R3-4, null, 1)

_Lambda$__R3-3  →  _Lambda$__3-0  →  throw new Exception(限制文案)
```

2.13.1.1 的同名方法是：

```
PageLoaderInit(..., ModDownload::DlClientListLoader, _Lambda$__R2-3, null, 1)
```

即：**旧版直接用共享 loader，新版用了一个注定失败的替身**。

## 6. 补丁点

只改 `LoaderInit` 里那 48 字节（IL_001A..IL_004A）：

```
-  ldstr "关闭下载" ... newobj LoaderTask`2::.ctor     （构造受限 loader，48 字节）
+  ldsfld PCL.ModDownload::DlClientListLoader          （6 字节）
+  42 × nop                                            （等长填充）
```

选择等长替换的原因：

- 后续指令偏移量不变，分支目标不需要重算；
- 不触碰方法头、局部变量表、异常处理表；
- 不重写 PE 元数据，其它方法与资源的字节一个不动；
- 写入前校验区间首字节是 `ldstr`、区间无外部跳转引用；写入后重新反编译复核。

## 7. 未修复的部分

- `ModModpack::ModpackInstall()`（无参）：手动安装整合包的入口仍会提示限制。
  修复它需要把 8 条指令的方法体扩容为原版 40 条指令（跨方法体空间），
  需要改写方法头/局部变量表甚至新增 PE 节，风险显著高于本补丁，故未纳入 v1.0.0。
- 其余 3 处仅为文案/兜底分支，不影响功能。

## 8. 复现分析的方法

仓库 `tools/` 目录提供了本次使用的分析工具源码：

| 工具 | 用途 |
|---|---|
| `Ildump.cs` | 导出全部类型/方法/字段与方法的 IL 规范化哈希（用于 2.13 vs 2.99 逐方法对比） |
| `FindStr.cs` | 搜索引用指定字符串的方法，并列出调用者 |
| `DumpMethod.cs` | 按类型/方法名导出完整 IL |
| `FindRef.cs` | 在目标程序集里查找可复用的成员引用 |
| `Probe.cs` | 打印模块/资源/程序集引用结构 |
